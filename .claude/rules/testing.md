# Test File Rules

These rules apply whenever Claude is working on any file under `tests/`.

## Imports

- Import `test` and `expect` from `@fixtures/site.fixture` — never from `@playwright/test` directly
- Import page objects via their fixture properties, not by constructing them manually in tests

## Test Tags

- Every `test()` call must include at least one tag: `@smoke`, `@navigation`, `@forms`, `@functional`, `@visual`, or `@responsive`
- Append tags to the test title string: `test('homepage loads @smoke', ...)`
- Site-specific tests generated by the test-generator agent also get `@custom`

## Selectors and Locators

- Never call `page.locator()` directly in a test body — use page object methods and properties
- If a locator is needed once and is truly test-specific, use `page.getByRole()` or `page.getByText()`
- Prefer accessible locators: `getByRole` > `getByText` > `getByLabel` > CSS selector

## Waiting and Timing

- Never use `page.waitForTimeout()` — rely on Playwright auto-waiting and `waitForSelector`
- Use `expect(locator).toBeVisible({ timeout: 10_000 })` for elements that may take time to appear
- Use `await page.waitForLoadState('networkidle')` when you need full page settle

## Test Isolation

- Each `test()` must be independent — no shared mutable state between tests
- Use `test.beforeEach` for navigation, never in `test.beforeAll` unless the page is truly static
- Do not rely on test execution order

## Forbidden Actions

- Never submit a form — test field presence, validation errors, and accessibility only
- Never hardcode the site URL — use `siteConfig.url` from the fixture
- Never create accounts or authenticate (unless `auth.required: true` in `site.config.json`)
- Never use `any` type without an explicit comment justifying it
